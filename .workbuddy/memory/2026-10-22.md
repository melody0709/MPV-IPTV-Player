## web.m3u 回看格式调研（只读，未改代码）

问题：G:\SynologyDrive\web.m3u 回看不支持，出方案待批准。

根因（两处独立缺陷，需同时修）：
1. `utils.lua:175-189 replace_catchup_time_params` 只覆盖 3 种宏（`${utc:yyyyMMddHHmmss}`、`${(b)...|UTC}`、`${(b)...:utc}`），web.m3u 用的 `${(b)yyyyMMddHHmmss}-${(e)yyyyMMddHHmmss}`（无时区后缀）三条全不命中 → 占位符原样保留。
2. `catchup="append"` 语义缺失：web.m3u 的 catchup-source 是 `?playseek=...` 相对 query 片段，`build_catchup_playback_sources`(playback.lua:597) 与 `play-catchup`(main.lua:416) 把替换结果直接当 URL，没有拼接到直播 URL。

实测（curl 只读）：
- `http://10.10.10.187:8767/cctv13.m3u8?playseek=20261021200000-20261021210000` → `#EXT-X-PROGRAM-DATE-TIME:2026-10-21T19:59:54+08:00`
- 服务端把 playseek 字面值按 **+08:00 墙钟（北京时间）**解释；本机系统时区是 **PDT**，无后缀宏按"设备本地"填充会偏 15 小时 → 方案需时区覆盖手段。
- APTV 官方语义（docs.aptvapp.com/play/playseek）：`catchup="append"`+`?playseek=${(b)...}-${(e)...}` 是 APTV 默认回看格式；无后缀宏 = 设备本地时间，`:utc`/`|UTC` = UTC（Issue #84 印证）。

兼容面：cache 中 443 条 `catchup="default"`（完整 URL + `|UTC`，183.235.162.80 那批）现状已工作不能回归；53 条 `catchup="append"` 即 web.m3u。
架构预留：`data.lua:1281 path_matches_active_catchup` 已保护"直播 URL + query"形态的回看 URL，append 产物与其兼容。

方案要点（P0：宏解析泛化 + append 拼接；P1：时区后缀/配置覆盖；P2：catchup-days 过滤等）已提交用户待批。
